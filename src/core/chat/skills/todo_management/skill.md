# When to use
- ผู้ใช้ขอจัดการรายการ to-do (เพิ่ม, เสร็จแล้ว, ลบ, ดูทั้งหมด)
- ผู้ใช้ถามถึง "สิ่งที่ต้องทำ" / "งาน" / "todo" — ใช้ skill นี้เสมอ แม้ในประโยคจะมีคำเวลา เช่น "วันนี้", "สัปดาห์นี้"
  ตัวอย่าง: "วันนี้มีอะไรต้องทำบ้าง", "มี todo อะไรบ้าง", "งานในรายการมีอะไร"
  → `manage_todos(action='list')` — **list ทุกตัวทั้งที่เสร็จแล้วและยังไม่เสร็จ** ห้ามใส่ `filter.completed`

# When to filter by completed status
- ใส่ `filter.completed: false` **เฉพาะ**เมื่อ user ระบุชัดว่าต้องการเฉพาะที่ยังไม่เสร็จ เช่น "ของที่ยังไม่เสร็จ", "งานที่ค้างอยู่", "todo ที่ยังไม่ได้ติ๊ก"
- ใส่ `filter.completed: true` **เฉพาะ**เมื่อ user ระบุชัดว่าต้องการเฉพาะที่เสร็จแล้ว เช่น "todo ที่เสร็จไปแล้ว", "งานที่ติ๊กแล้ว"
- คำถามทั่วไป "มีอะไรต้องทำ" / "todo ของฉัน" → **ไม่ใส่ filter** (default: list ทั้งหมด)

# When NOT to use (ใช้ manage_schedules แทน)
- ผู้ใช้พูดถึง **นัดหมาย/ประชุม/เหตุการณ์ที่มีเวลาเฉพาะ** เช่น "นัดหมอ 10 โมง", "ประชุมพรุ่งนี้", "ตารางวันนี้"
- ผู้ใช้ขอ "เตือน" / "แจ้งเตือน" / "นัดเวลา" — เป็น schedule ไม่ใช่ todo

# Important: Todo ไม่มีฟิลด์วันที่
- todo model มีแค่ `title` + `completed` — **ไม่มี `due_date` หรือ `scheduled_at`**
- คำว่า "วันนี้", "พรุ่งนี้", "สัปดาห์นี้" ที่อยู่ในประโยคถาม todo → ถือเป็นคำเสริม ไม่ต้องเอาไป filter (เพราะ filter ไม่ได้)

# Rules
- ต้องมี `title` ตอนสร้างใหม่
- การ get/update/delete ต้องระบุ `uuid` ของ todo
- `list` รองรับ pagination (page เริ่ม 1, limit ค่า default 10)
