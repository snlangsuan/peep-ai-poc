# When to use
- ผู้ใช้ขอจัดการรายการ to-do (เพิ่ม, เสร็จแล้ว, ลบ, ดูทั้งหมด)
- ผู้ใช้ถามถึง "สิ่งที่ต้องทำ" / "งาน" / "todo" — ใช้ skill นี้เสมอ แม้ในประโยคจะมีคำเวลา เช่น "วันนี้", "สัปดาห์นี้"
  ตัวอย่าง: "วันนี้มีอะไรต้องทำบ้าง", "มี todo อะไรบ้าง", "งานในรายการมีอะไร"
  → `manage_todos(action='list')` — **list ทุกตัวทั้งที่เสร็จแล้วและยังไม่เสร็จ** ห้ามใส่ `filter.completed`

# When to filter by completed status
- ใส่ `filter.completed: false` **เฉพาะ**เมื่อ user ระบุชัดว่าต้องการเฉพาะที่ยังไม่เสร็จ เช่น "ของที่ยังไม่เสร็จ", "งานที่ค้างอยู่", "todo ที่ยังไม่ได้ติ๊ก"
- ใส่ `filter.completed: true` **เฉพาะ**เมื่อ user ระบุชัดว่าต้องการเฉพาะที่เสร็จแล้ว เช่น "todo ที่เสร็จไปแล้ว", "งานที่ติ๊กแล้ว"
- คำถามทั่วไป "มีอะไรต้องทำ" / "todo ของฉัน" → **ไม่ใส่ filter** (default: list ทั้งหมด)

# When NOT to use (ใช้ manage_schedules แทน)
- ผู้ใช้พูดถึง **นัดหมาย/ประชุม/เหตุการณ์ที่มีเวลาเฉพาะ** เช่น "นัดหมอ 10 โมง", "ประชุมพรุ่งนี้", "ตารางวันนี้"
- ผู้ใช้ขอ "เตือน" / "แจ้งเตือน" / "นัดเวลา" — เป็น schedule ไม่ใช่ todo

# Important: Todo ไม่มีฟิลด์วันที่
- todo model มีแค่ `title` + `completed` — **ไม่มี `due_date` หรือ `scheduled_at`**
- คำว่า "วันนี้", "พรุ่งนี้", "สัปดาห์นี้" ที่อยู่ในประโยคถาม todo → ถือเป็นคำเสริม ไม่ต้องเอาไป filter (เพราะ filter ไม่ได้)

# Parsing todo items ตอนสร้าง (สำคัญ — ตรวจให้ดี)
- ถ้าข้อความมีหลายงาน ให้แยกเป็นหลาย item แล้วส่งเป็น `todos` array (action `create`) — ไม่ใช่ยัดรวมเป็น title เดียว
- **ขึ้นบรรทัดใหม่ (new line) = คนละ item เสมอ** เช่น "ซื้อนม / ซักผ้า / โทรหาแม่" (แต่ละบรรทัด) → 3 todos
- **จุลภาค (comma) = แยกตามบริบท** ส่วนใหญ่คือคนละงาน เช่น "ซื้อนม, ซักผ้า, โทรหาแม่" → 3 todos
  แต่ถ้าจุลภาคเป็นรายละเอียดของงานเดียว **ห้ามแยก** เช่น "ซื้อของ: นม, ไข่, ขนมปัง" → 1 todo เพราะ นม/ไข่/ขนมปัง เป็นรายละเอียดของงานเดียวกัน
- ถ้าไม่แน่ใจว่าควรแยกหรือรวม (ประโยคยาว/กำกวม) ให้ถามผู้ใช้สั้น ๆ ก่อนว่าต้องการกี่รายการ
- เก็บ title ให้ตรงตามที่ผู้ใช้พิมพ์ ไม่ตัดทอน ไม่เติมเอง

# Delete confirmation (สำคัญตอน delete — ห้ามลบทันที)
- เมื่อผู้ใช้ขอ "ลบ/เอาออก" รายการ todo ให้เรียก `manage_todos(action='delete', uuid=...)` **โดยยังไม่ต้องส่ง `confirm`**
- ถ้ายังไม่รู้ uuid (ผู้ใช้ระบุด้วยชื่องาน) ให้ `manage_todos(action='list', lookup=true)` หาก่อน — **ต้องใส่ `lookup=true` เสมอ** เพื่อไม่ให้ขึ้นการ์ดรายการให้ผู้ใช้ระหว่างหา — ถ้าเจอหลายรายการที่ตรง ให้ถามว่าหมายถึงอันไหน
- tool จะคืน `status: "needs_confirmation"` (reason `delete`) พร้อม `target`: **ห้ามลบทันที** ให้แจ้งผู้ใช้ว่ากำลังจะลบรายการไหน (ระบุชื่อจาก `target.title`) แล้วถามยืนยัน
- ถ้าผู้ใช้ "ยืนยัน" ให้เรียก `manage_todos(action='delete', uuid เดิม, confirm=true)` เพื่อลบจริง
- ถ้าผู้ใช้ปฏิเสธ → ไม่ต้องลบ — **ห้ามตั้ง `confirm=true` เองถ้าผู้ใช้ยังไม่ได้ยืนยัน**

# Rules
- ต้องมี `title` (สร้างเดี่ยว) หรือ `todos` array (สร้างหลายรายการ) ตอนสร้างใหม่
- การ get/update/delete ต้องระบุ `uuid` ของ todo
- `list` รองรับ pagination (page เริ่ม 1, limit ค่า default 10)
