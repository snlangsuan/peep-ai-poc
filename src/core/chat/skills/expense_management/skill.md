# When to use
- ผู้ใช้บันทึกรายการเงิน (รายได้/รายจ่าย), ดู/สรุปรายการ, แก้ไข, ลบ

# Rules
- ตอน `create` ต้องมีจำนวนเงินและประเภท (รายรับหรือรายจ่าย) อย่างชัดเจน
- ก่อนเรียก tool `manage_expenses(action=create)` ต้องมั่นใจ 100% ว่าผู้ใช้ตั้งใจบันทึกค่าใช้จ่ายและรู้ประเภท (income/expense) ชัดเจน ถ้ายังไม่ชัด ต้อง "ถามผู้ใช้ก่อน" ห้ามเดา
- ตัวอย่างข้อความ unambiguous (เรียก tool ได้เลย):
  - "ซื้อกาแฟ 50 บาท", "จ่ายค่าน้ำ 200" → expense
  - "ขายของได้ 500", "ลูกค้าโอนมา 800" → income
- ตัวอย่างข้อความ ambiguous (ต้องถาม confirm ก่อนทุกครั้ง):
  - "เจอลูกค้า 120" → 120 บาทคืออะไร? ได้เงินจากลูกค้า, จ่ายให้ลูกค้า, หรือจำนวนคน? และถ้าเป็นเงิน เป็น income หรือ expense?
  - "ค่ากาแฟ" (ไม่มีจำนวน), "เมื่อกี้ 100" (ไม่มีบริบท), ตัวเลขลอย ๆ
- รูปแบบการถาม confirm: ถามสั้น ๆ เป็นภาษาไทย เสนอตัวเลือกที่เป็นไปได้ให้ผู้ใช้เลือก (เช่น "120 นี่คือรายได้จากลูกค้า หรือเป็นค่าใช้จ่ายให้ลูกค้าคะ?")
- **List action — MUST always provide BOTH startDate AND endDate** เวลา user ถาม "ค่าใช้จ่ายวันนี้/เมื่อวาน/สัปดาห์นี้/เดือนนี้" ให้ส่ง `filter.startDate` **และ** `filter.endDate` รูปแบบ `YYYY-MM-DD` ทั้งคู่เสมอ ห้ามส่งฟิลด์ใดฟิลด์หนึ่งโดด ๆ ห้ามเรียก list โดยไม่มี filter เมื่อ user ระบุช่วงเวลา
- การ map คำเป็นช่วงวันที่ (ใช้ค่าจาก Current Thai local time block ใน system prompt):
  - "วันนี้" → startDate = endDate = Today
  - "พรุ่งนี้" → startDate = endDate = Tomorrow
  - "เมื่อวาน" → startDate = endDate = Yesterday
  - "สัปดาห์นี้" → startDate = วันจันทร์, endDate = วันอาทิตย์ ของสัปดาห์ปัจจุบัน
  - "เดือนนี้" → startDate = วันที่ 1, endDate = วันสุดท้าย ของเดือนปัจจุบัน
- เคสตัวอย่าง: user "ค่าใช้จ่ายวันนี้" + Today=2026-05-31
  → `manage_expenses(action='list', filter={startDate:'2026-05-31', endDate:'2026-05-31'})`
- เวลาตอบสรุป ให้แสดงเป็นเงินบาทที่อ่านง่าย
