# When to use
- ผู้ใช้บันทึกรายการเงิน (รายได้/รายจ่าย), ดู/สรุปรายการ, แก้ไข, ลบ

# Delete confirmation (สำคัญตอน delete — ห้ามลบทันที)
- เมื่อผู้ใช้ขอ "ลบ/เอาออก" รายการค่าใช้จ่าย ให้เรียก `manage_expenses(action='delete', uuid=...)` **โดยยังไม่ต้องส่ง `confirm`**
- ถ้ายังไม่รู้ uuid (ผู้ใช้ระบุด้วยชื่อ/จำนวนเงิน) ให้ `manage_expenses(action='list', lookup=true, filter={...})` หาก่อน — **ต้องใส่ `lookup=true` เสมอ** เพื่อไม่ให้ขึ้นการ์ดรายการให้ผู้ใช้ระหว่างหา — ถ้าเจอหลายรายการที่ตรง ให้ถามว่าหมายถึงอันไหน
- tool จะคืน `status: "needs_confirmation"` (reason `delete`) พร้อม `target`: **ห้ามลบทันที** ให้แจ้งผู้ใช้ว่ากำลังจะลบรายการไหน (ระบุชื่อ/จำนวนเงิน/วันที่จาก `target`) แล้วถามยืนยัน
- ถ้าผู้ใช้ "ยืนยัน" ให้เรียก `manage_expenses(action='delete', uuid เดิม, confirm=true)` เพื่อลบจริง
- ถ้าผู้ใช้ปฏิเสธ → ไม่ต้องลบ — **ห้ามตั้ง `confirm=true` เองถ้าผู้ใช้ยังไม่ได้ยืนยัน**

# List vs Summary (เลือกให้ถูก — สำคัญมาก)
- ถ้าข้อความมีคำว่า **"สรุป", "ภาพรวม", "รวมยอด", "รายละเอียดค่าใช้จ่าย", "ใช้เงินไปกับอะไร"** หรือเป็นการขอดู **ช่วงเวลายาว (มากกว่า 1 เดือน เช่น "3 เดือน", "ไตรมาสนี้", "ปีนี้")** → **ต้องใช้ `action='summary'` เสมอ ห้ามใช้ `list`**
- ใช้ **`list`** เมื่อผู้ใช้อยากเห็น "รายการทีละอัน" (เช่น "แสดงรายการค่าใช้จ่าย", "ดูค่าใช้จ่ายวันนี้/เมื่อวาน", "มีรายการอะไรบ้าง") → ส่งการ์ด `expense`
- **`summary`** → ส่งการ์ด `expense_summary` (ยอดรวม + แยกตามหมวดหมู่)
- ตัวอย่างที่ต้องใช้ list → การ์ด `expense`:
  - "แสดงรายการค่าใช้จ่าย" (ไม่ระบุเวลา) → `manage_expenses(action='list')` **ไม่ต้องส่ง filter** (ระบบ default เป็นเดือนนี้) — **ห้าม** เดาว่าเป็น "วันนี้" เพราะวันนี้มักไม่มีรายการ
  - "ค่าใช้จ่ายวันนี้" → `action='list'` filter วันนี้
- ตัวอย่างที่ต้องใช้ summary (ห้ามพลาด) → การ์ด `expense_summary`:
  - "ขอรายละเอียดค่าใช้จ่าย" → `manage_expenses(action='summary')` (ไม่ระบุเวลา = เดือนนี้)
  - "สรุปค่าใช้จ่ายเดือนนี้" → `action='summary'` filter เดือนปัจจุบัน
  - "สรุปค่าใช้จ่ายในช่วง 3 เดือนนี้" + Today=2026-06-11 → `action='summary', filter={startDate:'2026-03-11', endDate:'2026-06-11'}`
- ทั้งสอง action: ถ้าผู้ใช้ระบุช่วงเวลา ต้องส่ง `filter.startDate`/`filter.endDate` (YYYY-MM-DD) ทั้งคู่ — **แต่ถ้าผู้ใช้ไม่ได้ระบุเวลาเลย ให้ไม่ต้องส่ง filter** (ปล่อยให้ระบบ default เป็นเดือนนี้) ห้ามใส่วันนี้เอง
- map คำเป็นช่วงวัน (เพิ่มจาก list ด้านล่าง):
  - "3 เดือนนี้ / ย้อนหลัง 3 เดือน" → startDate = Today ลบ 3 เดือน, endDate = Today
  - "ไตรมาสนี้" → ต้นไตรมาสปัจจุบัน .. Today
  - "ปีนี้" → 1 ม.ค. ของปีปัจจุบัน .. Today
- **`summary` จำกัดช่วงเวลาไม่เกิน 1 ปี** — ถ้าผู้ใช้ขอช่วงยาวกว่านั้น tool จะคืน `status: "invalid_range"` ให้แจ้งผู้ใช้ขอช่วงที่สั้นลง
- ถ้า `summary` ไม่ระบุช่วงเวลา ระบบ default เป็น **"วันนี้"**
- **ห้าม reuse ช่วงเวลาจาก turn ก่อนหน้า** — ถ้า turn ปัจจุบันผู้ใช้พิมพ์ "สรุปค่าใช้จ่าย" เฉย ๆ (ไม่ระบุเวลา) ห้ามใส่ filter ของช่วงเดิม (เช่น "3 เดือน" จาก turn ก่อน) — ให้ไม่ส่ง filter เพื่อให้ default เป็นวันนี้
- ถ้าไม่มีรายการในช่วงนั้น tool จะคืน `status: "empty"` → ตอบผู้ใช้เป็นข้อความว่าไม่มีรายการค่าใช้จ่ายในช่วงเวลานั้น (ไม่มีการ์ด)

# Rules
- ตอน `create` **ต้องส่ง `type` ทุกครั้ง**: `"income"` (รายรับ/เงินเข้า) หรือ `"expense"` (รายจ่าย/เงินออก) — `amount` เป็นบวกเสมอ ทิศทางอยู่ที่ `type`
- หมวดหมู่ (`category`) ต้องเลือกตาม `type`:
  - expense → `food&drink, transport, shopping, bills, work, other`
  - income → `salary, bonus, sale, transfer-in, refund, other-income`
- ก่อนเรียก tool `manage_expenses(action=create)` ต้องมั่นใจ 100% ว่าผู้ใช้ตั้งใจบันทึกและรู้ประเภท (income/expense) ชัดเจน ถ้ายังไม่ชัด ต้อง "ถามผู้ใช้ก่อน" ห้ามเดา
- การ `summary`/`list` จะคืน `income_total`, `expense_total`, `net_total` (= รายรับ − รายจ่าย) แยกกัน — เวลาสรุปให้ผู้ใช้ ถ้ามีทั้งรายรับและรายจ่าย ให้บอกทั้งสองฝั่งและยอดสุทธิ; ถ้ามีแต่รายจ่ายให้บอกยอดใช้จ่ายตามปกติ
- ถ้าผู้ใช้ถามเรื่อง "เงินคงเหลือ / เงินต้น / ยอดยกมา / งบเดือนนี้ (budget)" ให้ใช้ skill `account_management` (tool `manage_account`) ไม่ใช่ tool นี้
- ตัวอย่างข้อความ unambiguous (เรียก tool ได้เลย):
  - "ซื้อกาแฟ 50 บาท", "จ่ายค่าน้ำ 200" → expense
  - "ขายของได้ 500", "ลูกค้าโอนมา 800" → income
- ตัวอย่างข้อความ ambiguous (ต้องถาม confirm ก่อนทุกครั้ง):
  - "เจอลูกค้า 120" → 120 บาทคืออะไร? ได้เงินจากลูกค้า, จ่ายให้ลูกค้า, หรือจำนวนคน? และถ้าเป็นเงิน เป็น income หรือ expense?
  - "ค่ากาแฟ" (ไม่มีจำนวน), "เมื่อกี้ 100" (ไม่มีบริบท), ตัวเลขลอย ๆ
- รูปแบบการถาม confirm: ถามสั้น ๆ เป็นภาษาไทย เสนอตัวเลือกที่เป็นไปได้ให้ผู้ใช้เลือก (เช่น "120 นี่คือรายได้จากลูกค้า หรือเป็นค่าใช้จ่ายให้ลูกค้าคะ?")
- **List/Summary — เมื่อ user ระบุช่วงเวลา ต้องส่งทั้ง startDate และ endDate** (รูปแบบ `YYYY-MM-DD` ทั้งคู่ ห้ามส่งโดด ๆ) เช่น "ค่าใช้จ่ายวันนี้/เมื่อวาน/สัปดาห์นี้/เดือนนี้" — **แต่ถ้า user ไม่ได้ระบุเวลา ให้ไม่ต้องส่ง filter** (ระบบ default เป็นเดือนนี้) ห้ามเดาเป็น "วันนี้" เอง
- การ map คำเป็นช่วงวันที่ (ใช้ค่าจาก Current Thai local time block ใน system prompt):
  - "วันนี้" → startDate = endDate = Today
  - "พรุ่งนี้" → startDate = endDate = Tomorrow
  - "เมื่อวาน" → startDate = endDate = Yesterday
  - "สัปดาห์นี้" → startDate = วันจันทร์, endDate = วันอาทิตย์ ของสัปดาห์ปัจจุบัน
  - "เดือนนี้" → startDate = วันที่ 1, endDate = วันสุดท้าย ของเดือนปัจจุบัน
- เคสตัวอย่าง: user "ค่าใช้จ่ายวันนี้" + Today=2026-05-31
  → `manage_expenses(action='list', filter={startDate:'2026-05-31', endDate:'2026-05-31'})`
- เวลาตอบสรุป ให้แสดงเป็นเงินบาทที่อ่านง่าย
