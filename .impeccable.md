# Project "Gold Standard" Architecture & Coding Patterns

This document serves as the primary "Source of Truth" for all architectural and coding standards within the `omni-intelligence-studio-api` project. All new features and refactors must strictly adhere to these patterns.

## 1. Directory & File Naming
- **Feature Location**: `src/features/[feature]/v1/`
- **Component Naming**: `[feature].[subfeature].[type].ts`
  - *Reference*: `src/features/workspace/v1/workspace.channel.controller.ts`
- **Schema & Types**:
  - `[subfeature].schema.ts`: Zod schemas for validation and parsing.
  - `[subfeature].type.ts`: TypeScript types derived from Zod schemas.

## 2. Controller Standard
- **Structure**: Class-based with arrow function methods to preserve `this` context.
- **Generic Context**: Always use the explicit generic template for Hono's `Context`.
- **Validation**: Use `c.req.valid()` to access validated data.
- **Parsing**: All JSON responses MUST be parsed through a Zod schema before being returned.

```typescript
export class ExampleController {
  constructor(private readonly exampleService: ExampleService) {}

  create = async <
    E extends { Bindings: Bindings; Variables: Variables },
    P extends string,
    I extends JsonInputSchema<TCreatePayload>,
  >(c: Context<E, P, I>) => {
    const data = c.req.valid('json')
    const result = await this.exampleService.create(data)
    return c.json<TResponse>(responseSchema.parse(result), 201)
  }
}
```

## 3. Service & Repository Standard
- **Repository**:
  - Store in `[subfeature].repository.ts`.
  - Use central `prisma` client from `#/common/libs/prisma.lib`.
  - Explicitly define `Promise<Model>` return types.
- **Service**:
  - Store in `[subfeature].service.ts`.
  - Handle business logic and orchestration.
  - Throw **Custom Exceptions** from `#/common/exceptions/` (e.g., `ObjectNotFoundException`).

## 4. API Documentation Standard
- **Location**: `[subfeature].openapi.ts`.
- **Pattern**: Use `describeRoute` and `resolver` from `hono-openapi`.
- **Status Codes**: Use definitions from `#/common/constants/openapi.contant.ts` for consistent descriptions.

```typescript
export const createExampleDoc = describeRoute({
  summary: 'Create item',
  tags: [ERouteTag.EXAMPLE],
  responses: {
    201: {
      description: HTTP_ERROR_DESCRIPTIONS[201],
      content: { 'application/json': { schema: resolver(responseSchema) } },
    },
  },
})
```

## 5. Routing & Validation
- **Middleware**: Use `zValidator` from `#/core/middlewares/validator.middleware.ts` in the route definition file.
- **Grouping**: Register feature-level routes in `src/infrastructure/http/routes/v1/`.

---
*Note: Before starting any new feature, read an existing "Gold Standard" file like `workspace.channel.controller.ts` to ensure full compliance.*
